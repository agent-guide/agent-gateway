# v0.6.0

v0.6.0 adds HTTP Agent execution and native A2A ingress, introduces an xAI
Grok provider, and makes A2A activity visible through the gateway's existing
governance and observability surfaces.

## Added

### HTTP Agents Through A2A 1.0

- `runtime.type: http` Agents discover a remote A2A Protocol 1.0 Agent Card,
  select a same-origin `JSONRPC` interface, and publish immutable readiness
  snapshots.
- `protocol: agent` AgentRoutes translate the common
  `POST /<agent-route>/turn` contract to A2A `SendMessage` or
  `SendStreamingMessage`, including context continuity, input-required task
  resumption, and bounded best-effort cancellation.
- `protocol: a2a` AgentRoutes expose governed native ingress:
  - public, rewritten Agent Card discovery at
    `GET /<agent-route>/.well-known/agent-card.json`;
  - VirtualKey-governed JSON-RPC at `POST /<agent-route>`;
  - a six-method allowlist covering send, stream, task read/list/cancel, and
    task subscription;
  - byte-preserving request, JSON response, and validated SSE forwarding.
- The shared `pkg/a2a` layer now owns Card parsing/rewriting, bounded JSON-RPC
  inspection, the translating client, and the native governed proxy.

### HTTP Agent Governance

- Remote bearer credentials use the Agent-owned
  `http-agent:<agent_id>` credential scope and optional
  `runtime.http.auth_ref`.
- Native A2A ingress strips caller credentials, cookies, forwarding headers,
  and raw trace/depth headers before injecting the selected upstream
  credential and trusted correlation context.
- Redirects, cross-origin Card interfaces, unsupported security alternatives,
  push notification configuration, batches, and JSON-RPC notifications fail
  closed.
- Request, response, SSE-event, aggregate-stream, idle, connect, header, and
  total-time limits bound both translated and native paths.

### A2A Observability

- Native interactions carry `route_kind=agent`, `route_protocol=a2a`,
  `runtime_type=http`, Agent identity, operation, and bounded failure types.
- SQLite persists native A2A interactions in `a2a_usage_events`; unified
  interaction queries and OTLP export include those records.
- Prometheus request counters include HTTP/A2A traffic with bounded labels.

### xAI Grok Provider

- New built-in `provider_type: grok`, defaulting to
  `https://api.x.ai/v1`.
- Supports OpenAI-compatible Chat Completions and xAI's native Responses API,
  including streaming, tools, vision, `previous_response_id`, and Responses
  server tools such as `web_search` and `x_search`.
- Supports model-aware `reasoning_effort` handling and configurable capability
  overrides.

### Documentation

- Documentation now has explicit ownership: Design records durable decisions,
  Architecture records current runtime behavior, Plans contain active delivery
  work, and Release Notes record version outcomes.
- Added current HTTP Agent architecture, an HTTP Agent quick start and
  operations guide, and a native A2A ingress reference.
- Removed completed implementation plans and historical phase trackers after
  moving their durable content to permanent documents.

## Changed

- AgentRoute accepts `protocol: a2a` in addition to `protocol: agent`. Native
  A2A routes require a trusted host, GET and POST reachability, and a
  proxy-ready HTTP Agent at create/update time.
- The HTTP runtime manager is the single owner of Card discovery and shared
  Path A/Path B generations. Definition and credential changes refresh only
  affected entries and preserve unrelated ready snapshots.
- Managed credential updates reject credential-type changes; replace a
  credential instead of changing its type in place.
- Added the A2A Go v2.5.0 dependency and updated selected OpenTelemetry,
  `golang.org/x`, gRPC, protobuf, and supporting dependency versions.

## Fixed

- Native ingress never forwards an ingress `Authorization` or `x-api-key`
  VirtualKey to the remote Agent.
- HTTP `200` JSON-RPC rejections are marked as failed interactions with bounded
  error attribution.
- Invalid first SSE events are rejected as `-32006` before downstream commit;
  later stream failures terminate the stream and remain observable.
- SSE parsing handles CR, LF, CRLF, and buffer-aligned long lines without
  splitting valid events.
- Invalid params retain a valid JSON-RPC request ID and the correct response
  channel.
- `SubscribeToTask` gateway rejections use JSON, while successful subscriptions
  retain upstream SSE.
- Buffered native responses receive the same idle timeout as streams.
- Constructing a proxy without an explicit HTTP client no longer mutates
  `http.DefaultClient`.
- A2A interaction events are persisted instead of appearing only in
  Prometheus.

## Compatibility And Migration

- The repository's default policy does not preserve backward-compatible
  aliases. Configure the dispatcher with `agent`; the obsolete `acp` and
  `builtin` dispatcher subdirectives are not accepted.
- HTTP Agent credentials must use the exact `http-agent:<agent_id>` scope and
  must leave `provider_type` and `provider_id` empty.
- A native A2A client must send `A2A-Version: 1.0` and a non-null JSON-RPC ID.
  The gateway does not accept A2A v0.3 method names or Card shapes.
- SQLite creates the A2A usage table through the normal schema initialization;
  no separate manual data migration is required.

## Known Limitations

- Only A2A Protocol 1.0 JSON-RPC is supported for HTTP Agents; REST, gRPC,
  v0.3 compatibility, push webhooks, and extended-card discovery are not.
- Common HTTP Agent turns currently accept text input and remain
  request-bound.
- HTTP Agent session/task bindings are process-local and do not survive restart
  or move between replicas.
- Native A2A ingress targets HTTP Agents only; ACP and builtin Agents are not
  reverse-translated to A2A.
- Memory remains unimplemented; `/admin/memory/...` is reserved and returns
  `501 Not Implemented`.

## Verification

```bash

go test ./...
go vet ./...

```

The HTTP Agent suites additionally cover Card and interface selection,
credential ownership and replacement, lifecycle isolation, Path B task/session
mapping, Path A admission and error mapping, JSON byte preservation, and SSE
framing/limit behavior.
