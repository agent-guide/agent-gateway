# v0.6.1

v0.6.1 is a stabilization release for the HTTP Agent and native A2A features
introduced in v0.6.0. It adds a self-contained local A2A service, one shared
release-verification entry point, process-level binary smoke coverage, and
explicit SQLite upgrade tests. Gateway runtime contracts and configuration
shapes are unchanged.

## Added

### Local A2A Development Fixture

- `go run ./examples/a2a-agent` starts a loopback-only, deterministic A2A
  Protocol 1.0 JSON-RPC service with an Agent Card and readiness endpoint.
- The fixture implements `SendMessage` and `SendStreamingMessage`, retains a
  stable remote context, and finishes streams with a completed task status.
- The HTTP Agent quick start now supports a complete local walkthrough without
  a vendor account or outbound network dependency.
- The fixture is intentionally limited and is not a production Agent SDK.

### Release Verification

- `make verify-release` is the single release gate used by contributors and
  GitHub Actions. It checks tracked Go formatting without changing files,
  verifies modules, runs normal and race tests, runs `go vet`, and builds
  `agw`, `agwd`, and `agwctl`.
- The formatting file set and the temporary Anthropic race-test exclusion are
  owned by the shared script instead of duplicated between CI and release
  documentation.
- `make smoke-release` starts the built binaries on ephemeral loopback ports,
  applies an HTTP Agent through `agwctl`, and exercises common `/turn`, public
  Card discovery, native `SendMessage`, native `SendStreamingMessage`,
  VirtualKey termination, persisted A2A interaction lookup, and standalone
  `agwd` readiness.

### SQLite Upgrade Coverage

- Fresh-database tests assert all five usage event tables and their required
  indexes are initialized.
- A reviewable pre-v0.6 fixture retains representative LLM, MCP, ACP, and
  builtin rows while proving that production startup creates
  `a2a_usage_events` and its indexes.
- Post-upgrade tests write an A2A interaction through the production SQLite
  sink and read it through summary, recent-event, and unified interaction
  queries. The independent OTLP projection test covers the same A2A event
  family.

## Compatibility And Migration

- No API, route, bundle, credential, or database compatibility change is
  introduced by this patch release.
- Existing pre-v0.6 SQLite databases are upgraded through normal startup. No
  manual migration command is required, and existing usage rows are retained.

## Known Limitations

- Only A2A Protocol 1.0 JSON-RPC is supported for HTTP Agents; REST, gRPC,
  v0.3 compatibility, push webhooks, and extended-card discovery remain out of
  scope.
- HTTP Agent session/task bindings remain process-local and do not survive
  restart or move between replicas.
- The local A2A fixture implements only the two send methods and rejects other
  methods with JSON-RPC `-32601`.
- The race suite still excludes `pkg/llm/provider/anthropic` because the pinned
  `eino-ext/claude` dependency has a known race in `ChatModel.Stream`.

## Verification

Run both repository-owned release gates on the exact candidate commit:

```bash
make verify-release
make smoke-release
```

The candidate is ready to tag only after both commands pass from a clean
checkout and GitHub Actions is green for the same commit.
