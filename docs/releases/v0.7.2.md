# v0.7.2

v0.7.2 is a focused observability and runtime-maintenance release. It fixes
metrics aggregation and filtering, adds a unified interaction timeseries, and
updates the Eino core used by builtin Agents from v0.9.15 to v0.9.22. It does
not change persisted resource schemas or the protected Community extension
surfaces established by v0.7.0.

## Observability

- Average latency fields preserve fractional values across LLM, MCP, ACP,
  builtin, A2A, and unified interaction summaries. SQLite `AVG` results are no
  longer scanned through integer fields.
- `GET /admin/metrics/interactions/timeseries` aggregates the five typed
  interaction event families into one bucketed series. It accepts the same
  bounded interaction filters as the unified summary and recent-event APIs,
  including trusted Agent attribution.
- Timeseries bucket aliases and durations are validated before query dispatch,
  including when the usage query backend is unavailable. Invalid, non-positive,
  and sub-millisecond buckets return `400` instead of being echoed or reaching
  a zero-width query.
- Summary and breakdown filters are applied even when the filtered dimension is
  also selected as `group_by`.
- Regression coverage includes fractional averages for every typed event
  family, unified timeseries correlation filters, attribution fallback, and
  same-dimension grouping and filtering.

## Eino runtime maintenance

The Eino core is updated from v0.9.15 to v0.9.22 without changing the pinned
`eino-ext` components. The update brings the v0.9 checkpoint and stream-resume
corrections, deterministic in-memory filesystem query order, cancellation
checkpoint preservation, bounded `agentsmd` loading, cache-write token schema,
and provider file-reference schema into the builtin Agent runtime.

`runtime.builtin.middlewares.agentsmd.max_total_bytes` is now a strict
cumulative content cap. A document that crosses the remaining budget is
truncated at a valid UTF-8 boundary and later documents are omitted. A zero
value remains unlimited.

## Compatibility and migration

No database migration is required. Existing routes, provider configuration,
Agent definitions, VirtualKeys, credentials, Bundles, and extension envelopes
remain valid. The new unified timeseries route is additive. JSON clients should
accept fractional numbers in `avg_latency_ms`; this corrects a field that could
previously fail when SQLite returned a non-integral average.

Operators upgrading from before v0.7.0 must still complete every applicable
migration in the [upgrade guide](../guides/upgrade.md).

## Security and known limits

Official archives and images retain the v0.7.1 distribution boundaries: the
Community limiter is process-local, external credential refresh remains a
separately installed integration, and `/admin/memory/...` remains reserved
with `501 Not Implemented`.

Eino v0.9.22 retains an upstream data race in immediate cancellation of a
copied model stream. In this distribution the affected combination is a
streaming builtin Agent turn, force cancellation (or graceful cancellation
that escalates to force), and OTLP component tracing enabled. This issue also
exists in the previously pinned Eino v0.9.15; it is not introduced by this
upgrade. Operators that require avoidance can leave OTLP component tracing
disabled while retaining interaction spans, usage events, Prometheus metrics,
and non-component OTLP export.

The eino-ext Claude component remains pinned at v0.1.25 and retains its known
upstream streaming race. Release race coverage excludes only that provider
package and continues to cover the rest of the repository.
