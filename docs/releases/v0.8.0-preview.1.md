# v0.8.0-preview.1

This preview introduces governed MCP/HTTP API Connectors and independent LLM
model catalogs. It includes breaking configuration, Admin API, CLI and Go
package changes relative to v0.7.3. Use it to evaluate the new resource model;
preview interfaces and configuration may change again before v0.8.0.

Read the [upgrade guide](../guides/upgrade.md#upgrading-to-v080-preview1)
before replacing binaries. Existing SQLite stores can require stopped-service
conversion; startup does not silently migrate legacy MCP services or inline
logical models.

## Added and changed

- Connectors replace MCP services as the managed tool resource. MCP routes and
  builtin Agents resolve tools through shared Connector admission, leases,
  credential checks and execution identity. Connector IDs are immutable and
  case-sensitive; names are mutable display text.
- HTTP API Connectors define tools with JSON input schemas, bounded request
  mapping and response selection. They can be published through MCP routes or
  consumed by builtin Agents. Outbound execution applies HTTP policy, credential
  scope, bounded payloads, cancellation and typed outcomes; optional HTTP client
  spans and tool usage retain the calling Agent identity. See the
  [HTTP API example](../../examples/gateway.bundle.http-api.yaml).
- ProviderModels and LogicalModels are independent catalog resources. LLM
  routes explicitly expose either concrete ProviderModel references from one
  Provider or LogicalModel references. LogicalModels own aliases, scheduling
  and fallback; registering or discovering models never expands route exposure.
  Model listing returns only the published route-visible names.
- Responses tool namespaces support reversible flattening for Responses-via-Chat.
  Native Responses providers `openai`, `grok` and `codex` accept
  `options.responses_tool_namespaces` (`native` or `flatten`). Same-name tools
  in different namespaces retain distinct identities through requests, history,
  ordinary responses and SSE. Flattening requires explicit history and does
  not support `previous_response_id`; custom/deferred/search semantics require
  a native path.
- Strict JSON parsing rejects duplicate keys, malformed/trailing JSON and
  invalid encodings at the affected configuration and protocol boundaries.
  LLM route writes also reject unknown fields, including nested match/auth
  fields.
- Shared server assembly owns host credential/usage construction and shutdown.
  Agent execution contracts and runtime backends have clearer package boundaries.

## Fixes

- Responses and Claude Code Messages SSE parsing accepts `data:{...}` as well
  as `data: {...}`, with optional spacing after `event:`.
- Responses streaming stops at upstream EOF even without a terminal event,
  including empty or comment-only streams, avoiding a read loop.
- Builtin Agent usage includes turn/resume paths and attributed nested runtime
  activity.
- Example verification supplies the HTTP API example environment and fails
  when any Bundle validation fails, rather than hiding a failed `find -exec`
  validation behind a successful exit status.

## Compatibility and migration

- Replace `/admin/mcp/services` integrations with `/admin/connectors` and update
  Agent/MCP-route references to Connector IDs. Before opening an old store with
  either server or a store-opening CLI, stop all users of the store and run the
  explicit `--convert-connectors` repair. Static Connector definitions are
  rejected; manage them through Admin or Bundle apply.
- Replace Bundle `managedModels` with `providerModels`, add independent
  `logicalModels`, and update route targets to explicit references. Use offline
  `extract-models` for old inline logical definitions. Provider-only targets
  require `convert-target` with an explicit model allowlist. A ProviderModel
  route uses real upstream model names; put aliases and cross-provider choices
  in LogicalModels.
- CLI automation must replace `agwctl mcp-service` with `agwctl connector`.
  Concrete model inventory uses `agwctl model provider`; logical inventory uses
  `agwctl model logical`. Replace Admin `/admin/llm/models/managed` calls with
  `/admin/llm/models/provider`; independent logical resources use
  `/admin/llm/models/logical`. Create/update models through Admin or Bundle apply.
- HTTP API credentials use scope `connector:<id>` with empty Provider fields.
  Provision credentials separately; a Connector can be stored while unready.
  Connector references and active/queued execution prevent unsafe deletion or
  execution edits. Bundle apply remains sequential with partial success.
- Go consumers must update moved imports: `pkg/adminclient` → `pkg/admin/client`
  (`package client`), `pkg/gatewaybundle` → `pkg/gateway/bundle`, `pkg/agent/runtime` →
  `pkg/agent/execution`, and runtime adapters → `pkg/agent/runtimebackend`.
  Runtime assembly/configuration helpers moved under `internal/` are no longer
  importable by external modules; use the designated distribution entry points.
  Undesignated Go APIs remain subject to incompatible changes. Designated
  extension/distribution surfaces retain the
  [Enterprise extension contract](../design/enterprise-extension-contract.md).

Keep pre-upgrade binaries, static files and a consistent database backup. A
rollback must restore the matching data and configuration, not just the binary.
See [offline recovery](../guides/architecture-config-recovery.md) for the
conversion commands and transactional repair behavior.

## Known limits

The Community limiter is process-local. OAuth refresh requires an external
command. Memory, Agent budget enforcement, durable business workflows and
caller-isolated MCP sharing remain unimplemented. The upstream race limitations
documented in [v0.7.3](v0.7.3.md#known-limits) remain; configured release race
coverage excludes only the Anthropic provider package.

## Verification and publication

Local preparation passed `make verify-release` (including configured race
coverage and the checkout extension consumer), `make verify-adoption`,
`make smoke-release`, and `make verify-release-archive` on macOS arm64.
Linux arm64 `make smoke-container` and `make smoke-first-run` also passed,
including governed common/native Agent ingress, restart and idempotent apply.
All three binary manifests report edition and module version
`0.8.0-preview.1`. These checks exercised the preparation working tree;
immutable candidate verification runs against the committed release input.

Release preparation and published-artifact verification are separate. The tag
workflow requires source tests, configured race coverage, vet, builds, adoption
checks, process smoke and immutable consumer verification, then native archives,
multi-architecture images, image scans, anonymous pulls, first-run replay,
checksums, SBOM and provenance. Published artifacts are verified again after
GitHub Release publication. Private Enterprise acceptance is separate.

This tag is published as a GitHub prerelease and is not selected as the latest
GitHub release. Images receive the explicit `v0.8.0-preview.1` and source SHA
tags; preview publication does not move either image's `latest` tag.
