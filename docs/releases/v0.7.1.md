# v0.7.1

v0.7.1 is an adoption and distribution release. It does not change LLM, MCP,
ACP, A2A, Agent, Bundle, Admin API, or persisted resource contracts. It makes
the capabilities present in v0.7.0 installable and independently verifiable
without a repository checkout or provider account.

## Release artifacts

- Native archives are published for Linux amd64, Linux arm64, macOS amd64, and
  macOS arm64. Each contains `agw`, `agwd`, `agwctl`, the license, installation
  notes, and machine-readable build metadata.
- `SHA256SUMS` covers all four native archives and the first-run archive. A
  machine-readable SPDX JSON SBOM inventories the exact tagged source tree.
- The gateway and deterministic A2A fixture are separate multi-architecture
  images at `ghcr.io/agent-guide/agent-gateway:v0.7.1` and
  `ghcr.io/agent-guide/agent-gateway-a2a-fixture:v0.7.1`. The first-run asset
  pins both by their immutable manifest digests.
- GitHub workload identity produces artifact provenance without a long-lived
  signing secret. OCI SBOM and provenance attestations are attached to both
  images.

The gateway image contains all three Community binaries, defaults to `agwd`,
runs as UID/GID 10001, and uses `/var/lib/agent-gateway` as its writable state
directory. It contains no provider credential and does not include `agw-auth`.

## Provider-credential-free first run

`agent-gateway-first-run-v0.7.1.tar.gz` contains a standalone Compose project,
its byte-identical checked-in Bundle, placeholder-only environment template,
setup and smoke commands, and an optional observability profile. It requires no
local Go toolchain and no LLM provider key.

The default path proves:

- generated VirtualKey enforcement, including rejection without the key;
- a common Agent SSE turn through a deterministic HTTP/A2A fixture;
- governed native A2A Protocol 1.0 Card and JSON-RPC ingress;
- idempotent Bundle apply and SQLite persistence across container replacement;
- persisted interaction lookup and the exact successful HTTP Agent request
  counter.

The fixture is development infrastructure, not a production Agent SDK.
A successful fixture turn does not claim token usage or a failure sample.

## Optional evaluation paths

- The Compose `observability` profile provisions Prometheus, Tempo, an
  OpenTelemetry Collector, and Grafana with a checked-in dashboard. It uses
  existing gateway counters and OTLP spans; Prometheus does not expose a
  latency series. Anonymous Grafana access and 24-hour retention are for local
  evaluation only.
- The coding-agent guide and Bundle evaluate existing Codex or OpenCode ACP
  runtimes, exact-run cancellation, conditional session/transcript support,
  and interactive permission decisions. They require an externally installed
  ACP adapter, workspace, and upstream authentication. Claude Code remains a
  gateway client through the `cc` profile, not an ACP backend.

## Documentation and community

- The repository landing path now leads from product purpose to a checksummed,
  governed first request.
- Installation, upgrade, evaluated-capability, and coding-agent guides separate
  implemented behavior, external dependencies, and roadmap work.
- The English and Chinese product home pages provide synchronized Get Started
  and GitHub paths plus a concrete request and observable result.
- Contribution, private security-reporting, and focused issue templates make
  GitHub Issues the single public support destination. Discussions are not a
  second support channel for this release.

## Compatibility and migration

v0.7.1 adds no protocol or storage migration beyond v0.7.0. All protected
Community symbols first designated by v0.7.0 remain unchanged. Operators moving
from an earlier version must still complete every applicable v0.7.0 migration:
Admin body and compression boundaries, dynamic extension configuration, secret
references, and limiter schema/generation behavior are summarized in the
[upgrade guide](../guides/upgrade.md).

The `cliauth_token` to `oauth_token` SQL procedure is not a v0.7.x migration.
It applies only to stores that have not completed the external CLI-auth cutover
documented since v0.5.0. OAuth refresh still needs a separately installed
external command.

## Security and known limits

The release workflow scans both final images and rejects fixable HIGH or
CRITICAL findings. JSON scan results are retained with the workflow run; no
such finding is accepted silently. The public first-run replay deliberately
pulls the digest-pinned images without registry credentials.

The Community limiter remains process-local. Memory, distributed limiting,
high availability coordination, enterprise IAM/SSO, durable workflows,
scheduling, human Tasks, durable compliance audit, and cost-budget enforcement
remain roadmap capabilities. `/admin/memory/...` continues to return
`501 Not Implemented`.

## Verification and publication

The tag workflow rejects a release unless:

- source, race, vet, build, process-smoke, and exact-commit Community consumer
  gates pass;
- all four native archives execute their own manifest checks and both Linux
  archives pass the process smoke from extracted binaries;
- native amd64 and arm64 runners pass image identity, non-root, read-only,
  persistence, termination, and fixture health checks;
- a separate job with no registry login can pull both immutable image digests;
- the first-run archive passes exact-inventory, Bundle identity, local-mount,
  credential, checksum, and outside-checkout end-to-end checks;
- the tagged-source SBOM, archive checksums, and provenance are generated; and
- the published Release assets are downloaded again, checksummed, and the
  public first-run path succeeds without registry credentials.

GHCR creates a new container package with private visibility. On the first
publication of either image, an `agent-guide` organization owner must change the
new package to Public and rerun the failed workflow jobs. The workflow does not
publish the GitHub Release until the independent anonymous image-pull gate
passes; later releases reuse the public packages.

Only after those checks does automation move the two `latest` image tags. The
runtime manifests from `agw` and `agwd` and the validation manifest from
`agwctl` remain distinct, while every included Community version reports
`0.7.1`. `agw version` still reports the embedded Caddy version and is not the
Agent Gateway release identity.
