# v0.7.0

Release status: **Published**, 2026-10-13. Tag `v0.7.0` contains Community commit
`3d04b7a0207a6d31746a1b196ae9d82097c2087c`. Published-dependency acceptance
is complete for the designated surfaces below.

v0.7.0 adds a reusable extension foundation for independently compiled
distributions while preserving Community gateway protocol ownership. It does
not deliver commercial modules, enterprise IAM or a general plugin platform.

## Added and changed

- Public Caddy, standalone and CLI entry packages with independent command state,
  explicit linked-module assembly and public metrics options.
- Deterministic runtime/validation manifests, local `manifest` commands and
  authenticated `/admin/manifest` queries. Community edition and built-in module
  metadata report version `0.7.0`; these diagnostic values do not grant entitlements
  or establish released-tag compatibility.
- Registered extension envelopes owned solely by the existing ConfigStore,
  dynamic `/admin/extensions/{module_id}` CRUD, dependency-ordered CLI apply and
  reference-preserving export. Strict local validation is separate from server
  preparation; failed preparation/persistence preserves the serving generation.
- Trusted bounded attribution for identity and runtime correlation, plus two
  sanitized public operational event families with isolated bounded sink queues,
  cancellation, flush/shutdown behavior and health/drop/failure reporting.
- Module-owned Admin subroutes under `/admin/extensions/<module_id>/...`, with
  generation leases and the same mount authentication and middleware as Community.
- VirtualKey limiter backend selection for LLM/MCP/Agent admission, atomic consume,
  generation fencing, secure failure defaults and preserved unchanged policy state.
- Public contract suites and a separate-module consumer that builds all three
  entries and exercises both server modes. Independently maintained consumers
  can run the same contracts without importing Community internals.

## Compatibility and migration

All Admin routes now validate the complete received body before dispatch. Bodies
over 4 MiB return bounded JSON 413; compressed bodies return 415. Bundle apply
has a per-resource HTTP boundary, not a total local YAML-file boundary. Generic
panic responses return JSON 500 without arbitrary panic diagnostics.

Internal extension configuration is independent of Caddyfile. Configure it through
Admin API or Bundle apply. Caddyfile's extension directive and the Caddy app JSON
`extensions` field have been removed; standalone static Bundles reject non-empty
`extensions`. Move those envelopes into a Bundle and apply them through an
authenticated Admin mount. Startup/reload never automatically imports them into
the store. `extension.NewManager` now accepts only context, registry and
persistence; `BootstrapOptions.StaticExtensions`, `Envelope.Source` and
`GatewayBundle.ValidateForStaticConfigWithRegistry` have been removed from the
candidate APIs. Other resource families retain their existing configuration rules.

Configuration references use declared `{"$secret_ref":"env:NAME"}` fields;
literal secrets and undeclared reference objects fail. Local validation checks
syntax without requiring the environment variable. Server preparation resolves
separately, retaining reference tokens in storage/export.

The built-in limiter remains the default. Selection schema 1 accepts a linked,
configured backend, `timeout_ms` from 1–1000 (default 100), and `failure_mode`
(default `closed`). Exhaustion returns 429, backend failure returns bounded 503,
and explicit `open` mode permits degraded admission. Cancellation, shutdown and
retired policy errors never fail open. Ambiguous consumes are never retried.
Backend or policy changes reset/fence affected generations; unchanged dimensions
and unrelated prepared-handle refreshes preserve quota state.

## Limits

Only `limiter.admission` and `extension.mutation` public events are designated;
they are bounded to 16 KiB and delivered best effort, with no durable audit,
replay or full usage-export contract. Attribution does not implement IAM or
tenant isolation. The reference limiter is process-local; no production Redis
backend is supplied. Registration does not grant general request interception.

Guardrails, policy/identity/secret/retrieval SPIs, model health/circuit/selection
extensions, token/cost budgets, memory and durable workflows are not delivered
by this release. Existing logical-model fallback remains available with its
current stream-opening and credential semantics. See the
[domain ownership matrix](../design/enterprise-extension-contract.md#12-domain-extension-coverage-and-ownership).

The root race gate retains the known upstream `eino-ext/claude` streaming race
exclusion for `pkg/llm/provider/anthropic`.

## Verification and release sequence

Before tagging, run on the exact clean Community candidate:

```sh
make verify-release
make smoke-release
make test-extension-consumer-candidate COMMUNITY_COMMIT=<full-commit>
```

The paired consumer then runs its exact-commit candidate gate. After publishing
the Community tag, run `make test-extension-consumer-release` with fresh caches;
the paired repository pins the released dependency, resolves its checksums and
runs its own fresh-cache release gate. Record the results in the paired
compatibility manifest before claiming published-tag protection. Candidate
results cannot replace these final online checks.
