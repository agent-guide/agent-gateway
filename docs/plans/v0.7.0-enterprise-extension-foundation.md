# v0.7.0 Extension Foundation — Release Closure

## Scope and current state

The F0–F6 foundation implementation and F7 permanent integration documentation
are complete as candidates. Implementation history remains in Git; this active
plan now tracks release acceptance. The confirmed ConfigStore-only extension
configuration principle is implemented: API/Bundle apply manage persisted
envelopes, and static extension configuration paths have been removed.
It does not add model high availability or other domain products to v0.7.

Permanent sources of truth:

- [Enterprise Extension Contract](../design/enterprise-extension-contract.md):

## ConfigStore-only configuration

The implemented principle is recorded in
[Enterprise Extension Contract, section 11.3.1](../design/enterprise-extension-contract.md#1131-principle-host-independent-extension-configuration).
Caddyfile owns Caddy host wiring; internal extensions use only ConfigStore in
both server modes. API and Bundle apply retain dependency validation, failure
isolation, secret-reference preservation and generation leases. Static extension
inputs, source metadata and static ownership conflicts have been removed.
Provider, route and other resource configuration ownership is unchanged.

The public candidate signature changes are recorded in the release notes.
Historical candidate evidence above predates this implementation change.

## Remaining release work, in dependency order

1. Select the exact clean release commit; both repository-owned Community gates
   and remote CI must pass for that source. Publish the Community `v0.7.0` tag.
2. Run `make test-extension-consumer-release` after publication. Its fresh caches,
   pinned published dependency and `GOWORK=off` must succeed without replacements.
3. In the paired repository, resolve the published tag into `go.mod`/`go.sum`,
   run `scripts/verify-community release` from fresh caches and record actual
   tag/commit, command, toolchain and result in its compatibility manifest.
4. Verify paired release CI for that dependency, then declare only the designated
   package/symbol/tag surfaces protected. No repository-wide Enterprise-ready claim.
5. Delete both foundation plans and remove their index entries after permanent
   documents and manifests describe the accepted release.

The remote has no `v0.7.0` tag as checked on 2026-10-10. Local tags and candidate
replacements cannot satisfy published dependency acceptance. Neither a hosted
release nor a remote CI result is inferred from local checks. Commercial module,
license, SBOM and customer delivery gates remain independently owned.

## Deletion condition

Delete this plan only after the Community tag is published, both consumer
published-tag gates pass and the paired compatibility manifest records the
accepted dependency. Remove its entries from `docs/README.md` and
