# v0.7.0 Community Guardrails Plan

## 0. Plan Contract

This plan delivers the first implementation slice of the durable decisions in
[`../design/guardrails.md`](../design/guardrails.md). It targets `v0.7.0` and
is intentionally narrower than the full design.

The planning baseline is annotated tag `v0.6.0`, commit
`339b15afda5ea7e611de255091bdc6884d52c0e1`. Implementation starts from the
final `v0.6.1` tree and must re-audit package names, interfaces, and insertion
points before the first code commit. When this plan, the design, and the code
disagree, the code establishes current behavior, the design establishes the
durable intended contract, and this execution plan must be corrected.

The release objective is:

> provide a useful Community guardrail enforcement kernel for the shared
> provider-facing chat path, with safe rewriting, auditable decisions, and
> complete configuration and management surfaces.

Each numbered work package is independently reviewable and must keep the full
tree buildable and tested.

## 1. Committed v0.7.0 Scope

The release covers the normalized provider-facing `provider.ChatRequest` used
by:

- OpenAI Chat Completions ingress;
- Anthropic Messages ingress;
- the Claude Code-compatible `cc` profile;
- builtin Agent model calls that resolve through `RoutedProvider`.

It delivers:

- a runtime-neutral Guardrail engine and checker registry;
- `allow`, `redact`, and `block` decisions;
- `monitor` and `enforce` policy modes;
- explicit `fail_open` and `fail_closed` checker-failure behavior;
- bounded execution, timeout, cancellation, and panic containment;
- lossless clone-and-rewrite validation for supported chat content;
- a deterministic baseline sensitive-data checker;
- the `topic_filter` reference checker and generic internal-LLM checker
  dependency with structured-verdict validation;
- provider `trust_zone` classification and fail-closed validation of every
  provider candidate reachable through an internal checker route;
- immutable policy snapshots and route-policy reference validation;
- Gateway Bundle, Admin API, and `agwctl` management surfaces;
- sanitized decision events, SQLite retention/query support, bounded
  Prometheus metrics, and OTLP correlation;
- exact capability metadata for supported and unsupported operations.

## 2. Explicit Non-Goals

The following remain outside `v0.7.0` even though the design leaves extension
points for them:

- response or partial-stream inspection;
- OpenAI Responses and embeddings request inspection;
- MCP operation inspection;
- unified Agent `/turn` input inspection;
- native A2A Path A body inspection or rewriting;
- MCP-service trust-zone classification and the global
  `require_guardrails_for_external` gate, which require the broader MCP and
  operation coverage defined by the design and must not ship as a partial
  LLM-only gate;
- prompt-injection products, proprietary DLP/entity packs, policy-as-code,
  organization inheritance, or a false-positive review console;
- ACP process sandboxing, filesystem controls, or network egress firewalling;
- durable human review, Memory, Gateway Request Pipelines, or business
  Workflows;
- storing raw prompts, matched values, rewritten payloads, checker output, or
  secrets in decision events.

An operation configured to require Guardrails but not present in the published
coverage matrix fails closed. A route without a Guardrail policy preserves its
v0.6 behavior.

## 3. Work Package G0 — Contract Freeze And Dependency Audit

Before adding runtime code:

- re-audit `RoutedProvider`, route snapshots, protocol error mapping, the usage
  event pipeline, Gateway Bundle, Admin registration, and CLI command assembly;
- finalize the persisted policy/check shape and route-policy reference shape
  defined by the design;
- define stable bounded reason codes and checker error classes;
- define the exact supported chat segment kinds and redaction behavior;
- define provider `trust_zone` normalization and checker-route validation over
  direct targets and every logical-model fallback candidate;
- define protocol-specific pre-stream block mapping for OpenAI, Anthropic, and
  `cc` without adding a synthetic SSE stream;
- define the dispatcher coverage gate for explicitly protected but unsupported
  operations, including OpenAI Responses and local `count_tokens`;
- define how internal LLM checkers call an LLM route without recursive
  self-evaluation or a config dependency cycle;
- identify which Guardrail interfaces are protected Community extension
  surfaces under `enterprise-extension-contract.md`.

Deliverables:

- focused amendments to `docs/design/guardrails.md` only for unresolved durable
  decisions;
- a capability matrix used by runtime and Admin surfaces;
- contract tests for reason-code bounds, decision normalization, and unsupported
  operation behavior.

No implementation checklist or milestone state is added to the design page.

## 4. Work Package G1 — Core Engine And Checker SPI

Create the runtime-neutral core, expected under `pkg/guardrail/`, without a
dependency on Caddy, dispatcher packages, provider implementations, MCP, ACP,
or `pkg/agent`.

Core responsibilities:

- immutable `Input`, `Segment`, `Policy`, `Check`, `Verdict`, and `Decision`
  value contracts;
- deterministic policy/check ordering and verdict combination;
- checker registry and factory validation;
- monitor/enforce projection of effective versus proposed action;
- per-check and total evaluation deadlines;
- context cancellation and bounded concurrency;
- panic recovery with bounded error classification;
- explicit fail-open/fail-closed behavior;
- no mutation of caller-owned input.

Tests must cover ordering, conflicting verdicts, redaction composition,
timeouts, cancellation, panic containment, registry duplication, failure mode,
and race safety.

## 5. Work Package G2 — Policy, Trust Zones, And Runtime Snapshots

Make Guardrail policies first-class configuration objects:

- register the config-store schema and SQLite persistence;
- implement CRUD with create/update/delete reference guards;
- add a manager that validates the complete reference graph before publishing
  an immutable snapshot;
- add the durable optional `guardrail_policy_id` binding to the shared
  `routecore.AgentRouteConfig` envelope, but accept a non-empty binding in this
  release only on eligible LLM routes;
- reject a non-empty policy binding on MCP routes, unified Agent routes, native
  A2A routes, and any other operation family outside the published v0.7
  coverage matrix during route create/update and bundle/static validation;
  an unsupported binding must never be stored and silently ignored;
- validate checker-route dependencies and reject direct or indirect cycles;
- add `internal | external | unclassified` to provider configuration, normalize
  an omitted value to `unclassified`, and carry it through Admin, bundle,
  static configuration, and provider snapshots;
- require every direct or logical-model provider candidate reachable through
  an internal LLM checker route to be `internal`, including fallback
  candidates; reject `external` and `unclassified` dependencies in both
  `monitor` and `enforce` modes;
- ensure request hot paths never read ConfigStore;
- refresh only affected policy/route snapshots on mutation.

Gateway Bundle must support validate, apply, and export for policies and their
route bindings. Credentials and checker secrets remain credential references;
they are never embedded in exported policy YAML.

Verification includes fresh-store migration, referential integrity, atomic
publication, failed-update rollback, concurrent readers, bundle round-trip,
deletion guards, omitted trust-zone normalization, rejection of policy bindings
on uncovered route kinds/protocols, and rejection when any checker-route
fallback candidate is not internal.

## 6. Work Package G3 — Community Checkers

### G3.1 Deterministic sensitive-data checker

Implement a bounded baseline checker suitable for Community use:

- operate only on policy-selected normalized user-content segments;
- register the stable checker kind `pii_scan`;
- ship a documented, deterministic set of named common sensitive-value
  categories;
- support operator-supplied regular expressions with explicit count, pattern
  length, match-count, input-size, and execution bounds;
- return locations and replacement intent without exposing matched values in
  logs or events;
- support allow, redact through irreversible mask replacement, and block; never
  retain enough replacement metadata to reconstruct the matched value;
- optionally invoke the same bounded internal-LLM checker dependency used by
  model-backed checks, with the G3.2 trust-zone and verdict constraints;
- validate overlap and replacement boundaries before applying redaction;
- handle Unicode and structured chat parts without corrupting non-text parts.

### G3.2 Topic filter and generic internal-LLM checker dependency

- resolve an operator-selected LLM route through a narrow dependency supplied
  to the checker;
- implement the Community `topic_filter` structured verdict and bounded
  confidence/reason-code contract;
- accept protected content only after the policy manager has proved that every
  provider candidate reachable through the checker route is `internal`;
- require a versioned structured verdict schema;
- reject malformed, oversized, or unknown verdicts;
- enforce its own timeout and token/input bounds;
- prevent recursive Guardrail evaluation and dependency cycles;
- never treat model prose as an executable policy or replacement payload.

The LLM checker is optional. A deployment using only deterministic checks must
remain fully functional. `monitor` mode uses the same trust-zone validation as
`enforce`; it never sends content to an external or unclassified dependency.

## 7. Work Package G4 — Typed Chat Inspection And Safe Rewrite

Build the `provider.ChatRequest` inspection adapter:

- clone every supported request without sharing mutable content with the
  caller;
- project only policy-declared user-content segments;
- preserve roles, ordering, tool-call identity, tool results, images, and
  protocol state not selected for inspection;
- apply redaction only to validated text ranges;
- reject a rewrite that cannot be represented losslessly;
- publish precise coverage metadata for unsupported part/state combinations.

Tests use request fixtures from OpenAI, Anthropic, `cc`, tool-use continuation,
multimodal, and builtin model-call paths. Round-trip tests prove that an
`allow` decision is byte/field neutral at the normalized provider contract and
that redaction changes only approved text.

## 8. Work Package G5 — Coverage Gate And RoutedProvider Enforcement

Before provider or local execution, add a dispatcher coverage gate for routes
with an explicit Guardrail policy:

- supported chat operations proceed to the `RoutedProvider` evaluation hook;
- unsupported OpenAI Responses operations fail closed before
  `CreateResponses` or `StreamResponses` can select or call a provider;
- unsupported local operations such as `cc` `count_tokens` fail closed before
  local execution when the route explicitly binds a Guardrail policy;
- without an explicit Guardrail policy, local and provider operations preserve
  their v0.6 behavior;
- the deferred global external-target gate does not implicitly classify a
  local, no-egress operation.

Insert evaluation at the start of `pkg/gateway.RoutedProvider.ExecuteChat` and
`ExecuteStreamChat`, after attached request requirements have been validated
and before `executeWithFallback` can select a credential or invoke a provider.
The compatibility `Chat` and `StreamChat` wrappers must continue to delegate to
those guarded execution methods rather than introducing a second hook.

Required invariants:

- evaluate the cloned request once per routed execution, not once per provider
  fallback candidate; multiple model executions within one Agent turn,
  including later tool-result continuations, are evaluated independently;
- reuse the accepted or rewritten request for every fallback attempt;
- do not select a credential or call a protected provider after a block;
- preserve existing candidate filtering, credential scheduling, retry, native
  relay, trace, and usage behavior;
- builtin `Generate`, `Stream`, and `WithTools` model calls reach the same hook;
- a route without a bound policy incurs only a snapshot lookup and preserves
  existing behavior;
- checker cancellation follows client/request cancellation.

The typed block error must map through the existing pre-stream JSON error path
for OpenAI, Anthropic, and `cc`. No handler starts an SSE response solely to
report a Guardrail rejection.

End-to-end tests cover batch and streaming requests, fallback, monitor mode,
enforce allow/redact/block, checker failure modes, builtin nested model calls,
and proof that blocked traffic never reaches the upstream server.

## 9. Work Package G6 — Admin, Bundle, And CLI Surfaces

Implement the management contract from the design:

- policy CRUD under `/admin/guardrails/policies`;
- provider trust-zone configuration and validation through the existing
  provider Admin and bundle surfaces;
- capability and sanitized recent-decision inspection under
  `/admin/guardrails/runtime/...`;
- Gateway Bundle policy/binding validation, apply, and export;
- `agwctl guardrails` list/get/capabilities/decisions/validate commands;
- declarative mutation remains through `agwctl apply`;
- `cmd/agw`, `cmd/agwd`, and `cmd/agwctl` blank-import the same Community checker
  registry; local `agwctl apply` and `agwctl guardrails validate` recognize the
  same built-in checker kinds exposed by the Caddy and standalone assemblies.

Admin responses distinguish invalid policy, missing dependency, dependency
cycle, unsupported operation, checker unavailable, and snapshot-not-ready
without returning raw inspected content.

## 10. Work Package G7 — Decision Observability

Emit one sanitized decision event for each evaluated operation through the
existing asynchronous event pipeline.

Persist and export only bounded metadata defined by the design, including:

- interaction trace/span linkage and available route, Agent, run, and
  VirtualKey attribution;
- policy ID/version/mode;
- protocol and operation;
- proposed and effective action;
- egress-performed flag;
- bounded reason code;
- per-check kind, outcome, latency, and bounded error class.

Add:

- a dedicated SQLite event table, migration, retention, and bounded queries;
- Admin recent-decision queries;
- OTLP span/event projection;
- Prometheus counters and latency histograms using bounded labels only;
- pipeline drop/failure coverage consistent with existing usage events.

Tests prove that prompts, matches, replacements, checker responses,
credentials, and arbitrary error strings cannot reach storage, metrics labels,
or exported attributes.

## 11. Work Package G8 — Documentation And Release Closure

After runtime behavior is complete:

- re-scope `docs/design/guardrails.md` so its page-level capability status and
  coverage matrix describe the delivered contract; keep undelivered extensions
  explicitly separated as Proposed rather than marking the full original scope
  Implemented;
- add current runtime flow to architecture documentation;
- add a first-run Guardrails guide and configuration/reference pages;
- update bundle, Admin API, CLI, README, root/nested `AGENTS.md`, and example
  configuration;
- update both language versions of every affected website page;
- add `docs/releases/v0.7.0.md` with compatibility notes, coverage matrix,
  limitations, and verification evidence;
- remove claims that imply response, MCP, Agent, or native A2A inspection when
  those paths remain unsupported.

## 12. Acceptance Gates

The release candidate must satisfy:

- the shared non-mutating formatting check reports no tracked Go files that
  require formatting;
- `go mod verify`, `go test ./...`, the repository race suite, `go vet ./...`,
  and `make build` pass;
- policy/check/config managers pass concurrent refresh and race tests;
- no ConfigStore read occurs on the request hot path;
- allow/redact/block and monitor/enforce/fail-open/fail-closed each have unit
  and end-to-end coverage;
- every supported protocol returns its native pre-stream block shape;
- a blocked request provably makes zero protected upstream calls;
- fallback evaluates once and reuses one validated rewrite;
- every provider candidate reachable through an internal checker route is
  classified `internal`, including monitor mode and fallback candidates;
- route and bundle validation reject non-empty policy bindings on MCP, Agent,
  native A2A, and every other operation outside the v0.7 coverage matrix;
- builtin nested and resumed model calls reach the same enforcement hook;
- explicitly protected Responses and local operations fail closed before
  provider or local execution and appear accurately in capability metadata;
- decision storage/export contains no inspected content or unbounded labels;
- bundle round-trip, Admin API, `agwctl`, Caddy, and standalone modes agree;
- `agw`, `agwd`, and `agwctl` expose or validate the same Community checker
  registry;
- upgrade tests preserve existing configuration and usage data;
- all permanent docs and paired website translations match the delivered
  coverage.

## 13. Recommended Commit Boundaries

Use at least these semantic commits; split further when reviewability requires:

1. `feat(guardrail): add bounded evaluation core`
2. `feat(guardrail): persist policies and publish snapshots`
3. `feat(guardrail): add community checkers`
4. `feat(guardrail): inspect and rewrite chat requests`
5. `feat(gateway): enforce guardrails in routed providers`
6. `feat(admin): expose guardrail management`
7. `feat(observability): persist guardrail decisions`
8. `test(guardrail): close end-to-end coverage`
9. `docs(guardrail): publish v0.7 operator contracts`

Every commit must pass targeted tests; commits that change shared request or
event contracts also run the full suite before landing.

## 14. Deletion Condition

Delete this plan after `v0.7.0` is tagged, every committed scope item is
delivered or explicitly re-homed into a future Proposed design, and permanent
design, architecture, guide, reference, `AGENTS.md`, website, and release-note
documents describe the resulting behavior. Remove the plan's entries from both
`docs/README.md` and `docs/plans/README.md` as part of deletion. Git history is
the implementation record.
