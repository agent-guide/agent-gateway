平台

你的 Agent 站立其上的网关。

AgentGuide 把三条运维路径放进同一个自托管 Runtime：LLM 网关负责模型访问， Connector 负责 MCP 与 HTTP 工具访问，Agent Runtime 负责执行 —— 共用一个控制平面、配置存储 和事件管道。

LLM 网关

一个 API 接入多个受支持的 Provider，减少客户端密钥暴露。

应用只面对一个端点和一把虚拟密钥。由网关决定这次请求真正由哪个提供商、 哪个上游模型、哪条凭据来服务 —— 并精确记录发生了什么。

routing

逻辑模型路由

先注册具体的 ProviderModel，再通过独立的 LogicalModel 复用这些绑定， 实现跨提供商选择与回退。路由显式暴露其中一种模型引用； 注册模型不会自动开放客户端访问，必须由路由发布。

  • LogicalModel 可暴露 chat-default 等别名，候选选择、调度和回退由逻辑模型管理。
  • ProviderModel 显式发布同一 Provider 下的具体上游绑定，使用真实模型名。
  • 模型目录 发现上游模型，独立管理 ProviderModel 和 LogicalModel；客户端模型列表只返回路由已暴露的名称。
  • 协议适配 支持 OpenAI Chat/Responses、Anthropic Messages 与 Claude Code 入口，按能力筛选候选；受支持的 Responses 转换保留工具命名空间内的独立身份。
credentials

池化、调度、按需刷新

上游凭据是受管对象，而不是应用配置里的字符串。 每个提供商可池化多条凭据并在其间调度，OAuth 类 CLI 凭据在请求时刷新。

  • 凭据池 每个提供商多条凭据，带选择状态与调度。
  • CLI 订阅登录 通过独立安装的 agw-auth 配套工具登录；OAuth 凭据接近过期时，网关调用外部刷新器。
  • 虚拟密钥 消费方永远接触不到上游密钥 —— 按应用或团队签发、轮换、吊销网关自有密钥。
  • fail-closed 鉴权 路由可强制要求虚拟密钥；未鉴权的流量到不了任何提供商。

Connector 与 MCP 网关

让 MCP 服务与 HTTP API 成为受治理的工具。

将 MCP 服务或 HTTP API 注册为 Connector（连接器），供 builtin Agent 调用， 或通过受 VirtualKey 保护的 MCP 路由发布。HTTP API 无需额外部署上游 MCP 服务。

目录

统一的 Connector 清单

发现 MCP 工具，或通过输入 Schema 和 GET/POST 映射定义 HTTP 工具。 Connector ID 稳定不变，修改显示名称不影响引用。 Builtin 工具选择要求在数量与页数上限内取得完整的 MCP 目录。

策略

受控的 HTTP 执行

HTTP 工具使用专属凭据、Schema 校验、出站策略、并发限制和调用期限。 默认允许公网 HTTPS，内网目标需显式配置宿主策略。 请求不会自动重试，POST 结果不确定时会明确告知调用方。

运维

巡检调用与执行结果

查看在途 MCP 请求，查询两类 Connector 的持久化工具事件。 HTTP 摘要记录状态、耗时与字节数，可选 OTLP Client Span 关联上游请求。 有引用或在途工作的 Connector 会拒绝执行配置变更与删除。 跨 Agent 共享 MCP 路由仍待实现调用方隔离的上游会话后开放。

控制平面

一切皆 API 对象，配置即代码。

提供商、模型资源、路由、凭据、虚拟密钥、Connector 和 Agent 都是持久化配置对象， Admin API 提供完整 CRUD —— 还有面向 GitOps 工作流的声明式 bundle 格式。

admin api

远程运营一切

Admin API 覆盖当前对象模型，外加运行时表面： 模型发现与刷新、MCP/ACP 运行时状态、待裁决的权限请求、指标查询。

  • 完整 CRUD Provider、ProviderModel、LogicalModel、路由、VirtualKey、凭据、Connector 与 Agent；静态资源在 Admin 中保持只读。
  • 运行时视图 池化 agent 实例、在途轮次与请求、待裁决权限。
  • 指标 API 汇总、统一交互与按协议时间序列、维度分解、近期事件、Prometheus 暴露端点。
  • 链接扩展 巡检发行版 Manifest，通过 Admin API 与 Bundle 管理已链接模块的配置。
  • 可插拔鉴权 挂在 basic auth、mTLS 或你的反向代理认证器之后。
agwctl + bundles

默认声明式

用一份可评审的 bundle 描述提供商、模型、路由、Connector 与 Agent。 本地校验、按依赖顺序应用、把线上状态导出回来。配置可以进入版本控制； apply 不是跨对象事务。

  • agwctl apply 一条命令推送完整的期望状态。
  • agwctl validate 在上线前拦住失效引用和非法定义。
  • agwctl export 快照线上配置，用于评审、diff 和备份。
  • 配置恢复 巡检并恢复结果未确认的 Agent、Provider 与 Connector 变更；配置阻止启动时，可通过离线工具备份并显式修复。

部署

当前能力说明以仓库源码为准。Connector 与显式模型资源变更新于本节 v0.7.3 体验包；体验这些功能请使用当前源码。

十分钟内完成无需模型 Provider Key 的首次运行。

已发布的 Compose 资产会启动网关和确定性 A2A Fixture，无需本地 Go 工具链 或模型 Provider 凭据。基础 Runtime 使用内嵌 SQLite；ACP Adapter、上游服务 和可选的外部凭据刷新器仍是独立集成。可选择基于 Caddy 的 agw 或独立守护进程 agwd，均可通过 agwctl 管理。 

curl -LO https://github.com/agent-guide/agent-gateway/releases/download/v0.7.3/agent-gateway-first-run-v0.7.3.tar.gz
curl -LO https://github.com/agent-guide/agent-gateway/releases/download/v0.7.3/SHA256SUMS
grep 'agent-gateway-first-run-v0.7.3.tar.gz' SHA256SUMS | sha256sum -c -
tar -xzf agent-gateway-first-run-v0.7.3.tar.gz
cd agent-gateway-first-run-v0.7.3
./setup.sh
./run-smoke.sh

macOS 请把 sha256sum -c - 替换为 shasum -a 256 -c -。测试通过会证明受保护的通用 Agent Turn、原生 A2A 入口、VirtualKey 执行、Interaction 持久化和请求指标均可工作。
