Platform

The gateway your agents stand on.

AgentGuide brings three operational paths into one self-hosted runtime: an LLM gateway for model access, Connectors for MCP and HTTP tools, and Agent runtimes for execution — with one control plane, config store, and event pipeline across them.

LLM gateway

One API across supported providers. Fewer keys exposed to clients.

Applications talk to one endpoint with one virtual key. The gateway decides which provider, which upstream model, and which credential actually serve the request — and records exactly what happened.

routing

Logical model routing

Register concrete ProviderModels, then reuse them in independent LogicalModels for cross-provider selection and fallback. Routes explicitly expose one kind of model reference; registering a model does not make it accessible to clients until a route publishes it.

  • LogicalModels Expose aliases such as chat-default; candidate selection, scheduling, and fallback belong to the logical model.
  • ProviderModels Publish explicit upstream model bindings from one Provider, using their real model names.
  • Model catalog Discover upstream models and manage ProviderModels and LogicalModels separately. Client model lists show only route-visible names.
  • Protocol adapters OpenAI Chat/Responses, Anthropic Messages, and Claude Code ingress; capability checks select compatible candidates. Responses tool namespaces retain distinct identities across supported conversions.
credentials

Pooled, scheduled, refreshed

Upstream credentials are managed objects, not strings in app config. Pool several credentials per provider, schedule across them, and refresh OAuth-style CLI credentials at request time.

  • Credential pool Multiple credentials per provider with selection state and scheduling.
  • CLI subscription auth Sign in through the separately installed agw-auth companion; the gateway invokes an external refresher for expiring OAuth credentials.
  • Virtual keys Consumers never see upstream secrets — issue, rotate, and revoke gateway-owned keys per app or team.
  • Fail-closed auth Routes can require a virtual key; unauthenticated traffic never reaches a provider.

Connectors & MCP gateway

MCP servers and HTTP APIs become governed tools.

Register MCP servers or HTTP APIs as Connectors. Use their tools in builtin Agents or publish them through VirtualKey-protected MCP routes. HTTP APIs need no upstream MCP server.

catalog

One Connector inventory

Discover MCP tools or define HTTP tools with input schemas and GET/POST mappings. Stable Connector IDs preserve references when display names change. Builtin tool selection requires a complete, bounded MCP catalog.

policy

Controlled HTTP execution

HTTP tools use scoped credentials, schema validation, egress policy, concurrency limits, and deadlines. The default allows public HTTPS; internal destinations need an explicit host policy. Calls are not retried automatically, and uncertain POST outcomes are reported to the caller.

operations

Inspect calls and outcomes

Inspect in-flight MCP requests and query persisted tool events for both Connector types. HTTP summaries record status, timing, and byte counts; optional OTLP client spans connect the upstream call to its tool execution. Referenced or busy Connectors reject execution changes and deletion. Shared MCP routes across Agents remain deferred pending caller-isolated upstream sessions.

Control plane

Everything is an API object. Config is code.

Providers, model resources, routes, credentials, virtual keys, Connectors, and Agents are persisted config objects with full CRUD over the Admin API — and a declarative bundle format for GitOps-style workflows.

admin api

Operate everything remotely

The Admin API covers the current object model, plus runtime surfaces: model discovery and refresh, MCP/ACP runtime state, pending permission decisions, and metrics queries.

  • Full CRUD Providers, ProviderModels, LogicalModels, routes, VirtualKeys, credentials, Connectors, and Agents. Static resources remain read-only through Admin.
  • Runtime views Pooled agent instances, in-flight turns and requests, pending permissions.
  • Metrics API Summaries, unified interaction and per-protocol timeseries, breakdowns, recent events, and Prometheus exposition.
  • Linked extensions Inspect the distribution manifest and manage linked module configuration through Admin APIs and Bundles.
  • Pluggable auth Mount behind basic auth, mTLS, or your reverse-proxy authenticator.
agwctl + bundles

Declarative by default

Describe providers, models, routes, Connectors, and Agents in one reviewable bundle. Validate it locally, apply objects in dependency order, and export the live state back out. Your gateway config can live in version control. Apply is not a cross-object transaction.

  • agwctl apply Push a full desired-state bundle in one command.
  • agwctl validate Catch broken references and invalid definitions before they ship.
  • agwctl export Snapshot live config for review, diff, and backup.
  • Configuration recovery Inspect and recover unconfirmed Agent, Provider, and Connector mutations. Offline repair supports explicit backed-up changes when invalid configuration prevents startup.

Deployment

The current capability overview follows repository source. Connector and explicit model-resource changes are newer than this v0.7.3 walkthrough; use current source for those features.

A provider-key-free first run in under ten minutes.

The published Compose asset starts the gateway and a deterministic A2A fixture without a local Go toolchain or model-provider credential. The base runtime uses embedded SQLite; ACP adapters, upstream services, and an optional external credential refresher remain separate integrations. Run the Caddy-based agw host or standalone agwd, and manage either with agwctl. 

curl -LO https://github.com/agent-guide/agent-gateway/releases/download/v0.7.3/agent-gateway-first-run-v0.7.3.tar.gz
curl -LO https://github.com/agent-guide/agent-gateway/releases/download/v0.7.3/SHA256SUMS
grep 'agent-gateway-first-run-v0.7.3.tar.gz' SHA256SUMS | sha256sum -c -
tar -xzf agent-gateway-first-run-v0.7.3.tar.gz
cd agent-gateway-first-run-v0.7.3
./setup.sh
./run-smoke.sh

On macOS, replace sha256sum -c - with shasum -a 256 -c -. A passing run proves protected common Agent turns, native A2A ingress, VirtualKey enforcement, interaction persistence, and request metrics.
