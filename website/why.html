Why AgentGuide

A control plane, not another agent framework.

LangGraph, AutoGen, and CrewAI answer "how should an agent think?" AgentGuide answers a different question: "how does an organization run agents?" — who may call them, what they may touch, and what evidence each governed request leaves behind. One builds agents. The other operates the shared runtime paths around them.

The distinction

Frameworks orchestrate reasoning. AgentGuide governs shared runtime paths.

A framework's workflow lives inside one agent process: plan, call a tool, reflect, retry. AgentGuide's control lives around the agent: identity, routes, runtime lifecycle, sessions, policy, and attribution. Durable tasks, schedules, and cross-agent workflows belong to an external upper layer and remain roadmap integration work.

better together

Keep your framework. Gain a control plane.

AgentGuide is deliberately not a replacement for your framework — it connects compatible framework-built agents to shared routes. The builtin runtime itself embeds an agent framework for its topologies; the gateway's job stays the same either way: definition, lifecycle, governance, resources, and observation.

  • Builtin runtime Declarative agents on an embedded framework — proof the two layers compose.
  • ACP runtime Codex, OpenCode, and other protocol-speaking agents, managed as black boxes.
  • HTTP runtime LangGraph, ADK, or custom services execute through translated A2A Protocol 1.0 turns or governed native A2A proxy ingress.
  • Protocol boundary ACP agents run as managed black boxes; external HTTP agents keep their implementation stack.

Choose the right tool

When AgentGuide fits — and when it does not.

AgentGuide is strongest when coding-agent runtime control and LLM/MCP governance need to share one self-hosted boundary. It is not the default answer for every AI gateway requirement.

good fit

Choose AgentGuide when

  • You need self-hosted runtime management for Codex, OpenCode, builtin, or remote A2A agents.
  • The same control point should govern Agent turns, supported LLM APIs, and MCP tools.
  • Private deployment, VirtualKeys, permissions, and operational evidence matter more than a hosted UI.
another path may fit better

Choose another tool — or wait — when

  • Your priority is the broadest LLM provider catalog, spend budgets, and an admin UI: evaluate LiteLLM.
  • You already standardize on Kong or Konnect and want their AI policies across LLM, MCP, and A2A traffic: evaluate Kong AI Gateway.
  • You primarily want a managed suite for LLM observability, guardrails, governance, and prompt management: evaluate PRISMA AIRS AI Gateway (formerly Portkey).
  • You require built-in enterprise SSO/RBAC, HA clustering, distributed rate limiting, budget enforcement, or a compliance audit ledger today: these are not current Community capabilities.

Where this is going

From governed agents to a larger capability network.

Teams may eventually operate many specialized agents through an external workflow layer. These are target abstractions — roadmap ideas, not capabilities in the current gateway.

vision · artifact bus

Work products, not prompt chains

Agents exchange versioned, auditable artifacts — a PRD, an architecture, a patch, a review — instead of raw text. Every artifact has a producer, consumers, versions, and an approval state, forming a lineage graph that answers "why did this fail?" in one query.

vision · capability composition

Ask for outcomes, not agents

Declare the capability you need — "review this contract", "release this service" — and let the platform resolve which agents combine to deliver it, wired together by the artifact types they consume and produce.

vision · agent teams

Invoke a team, not an agent

Named teams — PM, architect, coder, reviewer — as first-class objects with role routing and supervisor policy. The in-process supervisor and plan-execute topologies that ship today are the first step.

vision · shared memory

A blackboard for the fleet

Workspace-scoped memory that collaborating agents read and write — long-lived context that outlives any single session, governed like every other resource.
